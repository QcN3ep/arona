# Maintenance Guide

This book uses the default [mdBook](https://rust-lang.github.io/mdBook/) theme.
[mdbook-admonish](https://tommilligan.github.io/mdbook-admonish/) renders admonition blocks, [mdbook-pdf](https://github.com/HollowMan6/mdbook-pdf) exports PDF through Chromium, and `mdbook-pdf-outline` adds hierarchical chapter bookmarks to the PDF.

## Installing the Handbook Tools

The handbook build uses Rust tools, Python plugins managed by uv, and Chromium:

```sh
cargo install mdbook --version 0.4.51 --locked
cargo install mdbook-admonish --version 1.20.0 --locked
cargo install mdbook-pdf --version 0.1.11 --locked
UV_TOOL_BIN_DIR="$HOME/.cargo/bin" uv tool install mdbook-pdf-outline==0.1.6
export PATH="$HOME/.cargo/bin:$PATH"
```

These versions use the mdBook 0.4 interface.
The bookmark plugin is installed in the same executable directory as mdBook, and the PDF backend invokes Chromium to print pages.

## Preview and Export

```sh
cargo xtask book
cargo xtask book serve --open
```

The first command builds all outputs; the second starts a preview and rebuilds after source files change.
Both the HTML and PDF backends participate in the build and preview.

| Output | Path |
|---|---|
| HTML entry | `target/book/html/index.html` |
| PDF with chapter bookmarks | `docs/arona-book.pdf` |

`pdf-outline` uses the generated HTML and PDF to add hierarchical bookmarks based on body headings.
The final PDF uses A4 pages and is exported to `docs/` after each build.
A copy under `target/book/html/docs/` provides the website download.

## Chapters and Table of Contents

The table of contents is maintained in `book/src/SUMMARY.md`; the body is categorized by system, kernel, runtime, system services, tools, and contributing.
Table of contents entries link to body files, and chapters navigate to each other through relative links such as `../tools/xtask.md`.
`create-missing = false` in `book.toml` makes the build check whether the table of contents matches the body.

This book describes the behavior of the current code.
For interfaces, verify function signatures, permission requirements, errors, and resource lifetimes; for usage steps, verify build options, outputs, and actual results.
The body documents only implemented features, uses established terminology, and provides the necessary specification references.

Chapters unfold from the usage process or runtime flow, explaining how the parts work together.
Code snippets show calls, and tables are provided for looking up arguments and types.

## Shared Content and Plugin Assets

The contribution guidelines are included from the root `CONTRIBUTING.md`; just edit the original file.
The build configuration watches that file for changes.

The admonition syntax is:

````markdown
```admonish info title="Title"
Admonition content.
```
````

`book/mdbook-admonish.css` is the standard stylesheet generated by the plugin.
After upgrading the plugin, run `mdbook-admonish install .` in `book/` to update the assets, and check the stylesheet path and preprocessor configuration in `book.toml`.
The MIT license information for that stylesheet is recorded in `REUSE.toml` and `LICENSES/MIT.txt`.

`pdf-print-guard.js` disables the print page's automatic print job in automated browsers so the PDF renderer can start its own job.

After modifying the table of contents or body, rebuild and check HTML links, text rendering in the PDF, code layout, and bookmark navigation.
