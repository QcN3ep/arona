# 内核架构概览

在 Arona 中，一次文件读取会经过几个配合工作的部分：兼容服务解释 Linux 调用，文件服务查找文件，设备管理服务操作磁盘，内核在它们之间传递消息并调度线程。
沿着这次请求，可以看到系统怎样划分职责。

`arch` 和 `kernel` 共同组成特权态内核。
`arch` 封装指令和寄存器操作，`kernel` 维护内存、线程和对象等资源。
runtime 与系统服务运行在用户态，各服务拥有独立的地址空间，通过内核提供的 IPC 协作。

## 组成与依赖

| 目录 | 职责 |
|---|---|
| `arch/` | 固件交接、启动映像、硬件接口实现、特权指令和原始内存访问 |
| `kernel/` | 内存管理、Task、线程、IPC、能力和设备资源管理 |
| `abi/` | 内核与原生程序共同使用的对象类型、方法、权限、编码和返回值约定 |
| `components/runtime/` | 原生程序启动、Rust 运行环境及内核能力的 Rust 接口 |
| `components/` 中的服务 | 设备驱动、文件系统、日志及 Linux 兼容等系统功能 |

编译依赖从 `arch` 指向 `kernel`。
硬件接口定义在 `kernel::hardware`，架构层实现这些接口。
MMU、执行上下文、Trap、时钟与中断控制等能力都经这层接口供内核使用。

runtime 依赖 `abi`，把 Rust 接口转换为陷入内核的对象调用。
同一个服务的客户端库与服务程序可以共用协议类型；实际请求经通道进入服务所在的 Task。

## 框内核边界

Arona 的框内核设计思路来自 [Asterinas](https://github.com/asterinas/asterinas)。

`kernel` 的实现代码遵守不使用 `unsafe` 和条件编译的项目约束。
需要原始指针、内联汇编或硬件寄存器访问的实现放在 `arch`。
例如，页框分配策略和地址空间映射记录由内核维护，页表项读写和 TLB 操作通过硬件接口完成。

例如，建立一段用户映射时，内核分配页框、选择虚拟范围并登记映射引用。
随后 MMU 实现把这些决定写成当前架构的页表项，并完成 TLB 与指令同步。
页框和映射的状态由内存模块持有，架构实现负责完成对应的机器操作。

## 硬件能力如何绑定

硬件能力通过静态对象绑定到内核的槽位。
例如 `kernel::hardware::mmu()` 返回已绑定的 MMU 实现。
各槽位使用 `spin::Once` 保存实现，重复绑定返回 `AlreadyBound`，在完成绑定前直接取用会 panic。

架构层使用 `declare_hardware!` 声明静态实现，并把绑定函数放入 `arona_hardware` 链接段。
启动代码调用 `arch::hardware::bind()`，遍历该段并执行绑定函数。
具体硬件能力声明在各自模块内，启动入口统一完成绑定。

绑定完成后，内核按启动顺序初始化各项能力。
例如中断控制器从 `HardwareInfo` 取得拓扑，再通过内存模块建立 MMIO 映射，配置实际路由。

## 内核与系统服务

内核提供地址空间、线程、对象、句柄、消息传递和设备资源授权等机制。
系统服务使用这些机制实现各自的功能：

| 服务 | 当前职责 |
|---|---|
| init | 读取启动配置，加载和启动基础服务，启动并监督配置中的应用 |
| devmgr | 发现设备、建立驱动实例、管理设备会话和 I/O |
| logger | 收集用户日志，读取内核日志，输出并在 init 提供文件时持久化 |
| fs | 提供文件访问、路径与挂载管理，访问启动归档及 ext4 存储 |
| linux | 装载 Linux ELF，维护 Linux 进程语义并处理 Linux 系统调用 |

系统服务分别运行在 Task 中，使用独立的用户地址空间。
句柄指向可操作的内核对象，并携带允许执行的权限。
一个服务能访问哪些设备、内存或通道，取决于它获得的句柄。

内核中的设备资源管理与用户态驱动分别承担授权和操作职责。
前者控制 MMIO、DMA、PCI 和中断资源的授予及回收，后者处理设备协议和 I/O 请求。
驱动获得 Device 句柄后，通过这些授权访问寄存器、建立 DMA 映射并接收中断。

## 原生调用与 Linux 兼容

原生程序通过句柄调用对象方法。
方法号在对象类型下解释，内核在分派前根据方法检查所需权限。
runtime 把寄存器约定和编码封装为 Rust 接口。

Linux 程序使用 Linux ABI。
Linux 兼容服务通过内核的 Trap 接口接收受监督程序的系统调用和异常，维护进程、文件描述符、信号等状态，再调用原生内核机制和其他服务完成操作。
Linux 系统调用号的解释位于兼容服务中。

以磁盘文件的 `read` 为例，兼容服务从 fd 找到文件会话，把读取请求交给 fs。
fs 将文件偏移转换为磁盘块，经 devmgr 的块设备会话提交 I/O。
设备完成后，结果逐层返回，兼容服务把字节数写入 Linux 返回寄存器，再恢复应用线程。
Linux fd 和文件偏移由兼容服务维护，文件系统节点由 fs 维护，物理页框和线程由内核维护。

## 从启动到服务运行

1. 架构入口建立启动所需的映射与栈，读取固件交接信息。
2. 架构层解析 DTB，准备硬件描述、init 映像和 initramfs，并绑定硬件能力。
3. `boot_kernel` 初始化内存、Trap、中断控制器、定时器和调度器。
4. 内核创建 init 的 Task、地址空间、初始栈和线程，传递启动资源。
5. init 启动文件、设备管理、日志和 Linux 兼容服务，再读取应用配置。

启动过程也按这些职责逐步交接：内核建立首个 Task 后，init 接手原生服务的加载，Linux 兼容服务接手 Linux 应用的执行环境。
