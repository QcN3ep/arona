# 文件服务

fs 把启动归档和磁盘卷放进同一棵文件树。
打开 `/bin/init` 时，内容来自 cpio newc 归档；挂载持久化卷后，打开 `/var/log/system.log` 则进入 ext4。
两条路径都返回 File 会话，客户端通过相同的 IPC 接口读写，路径和文件内容经页框传递。

## 接口与会话

`Control` 管理文件服务，负责建立客户端、挂载和卸载文件系统。
`Client` 提供路径操作，`File` 和 `Directory` 表示已打开的会话。

| 接口 | 操作 |
|---|---|
| Client | 打开文件或目录、创建、查询元数据、建立目录、删除、重命名、硬链接与符号链接 |
| File | 按偏移读写、追加、截断、大小、元数据、属性修改、fsync |
| Directory | 元数据、属性、目录项读取以及相对路径操作的目录锚点 |
| Control | 连接客户端、挂载 ext4、卸载 |

同步客户端为请求指定绝对截止时间。
异步 `start_*` 接口返回 Pending 对象，调用者可在事件循环中等待并解码结果。
`ReadAt` 提供只读的按偏移访问。
init 的 ELF 加载器通过它先读 ELF 头，再定位程序头和各段内容，数据既可来自归档视图，也可来自文件会话。

打开文件时，客户端建立专用通道并交接其服务端端点。
fs 保存 FileSession，处理该会话上的请求，对端关闭后释放节点与待处理状态。

## newc 归档根

`Archive` 持有启动归档的 FrameAllocation 句柄，按 newc 条目建立有序路径索引。
解析检查头部、名称、数据边界、对齐、类型和归档结束标记。
文件视图通过共享持有的归档页框按偏移读取内容。

归档呈现普通文件、目录和符号链接，并保存 inode、权限、链接数和时间等元数据。
硬链接条目的身份和后备数据在建索引时解析。
归档根提供只读文件数据，持久化写入进入挂载的 ext4 卷。

根目录初始内容由打包器生成的归档决定。
系统程序位于 `/bin`，应用启动配置位于 `/etc/init.toml`，持久化卷由 init 挂到 `/var`。

## 路径解析与挂载

Namespace 组合归档与挂载表。
例如，将 ext4 挂载到 `/var` 后，解析 `/var/log/system.log` 会转入该卷；`/bin/init` 仍从归档查找。
列举目录时，挂载点合并到父目录的目录项中。
挂载操作检查目标路径、已挂载路径关系与磁盘范围占用。

目录锚点接口支持相对目录查找。
解析器处理绝对路径、相对路径、`.`、`..`、重复分隔符以及符号链接。
符号链接的绝对目标从命名空间根解析，相对目标从其父目录继续解析。
名称长度和路径长度在处理过程中检查，符号链接跟随次数最多为 40。

打开选项包括 write、create、exclusive、truncate 和权限位。
服务根据节点类型、创建条件与后端可写状态执行操作。
跨卷链接或重命名、忙碌挂载点及类型不符等情况有独立错误结果。

## 块设备访问

`Disk` 包装 devmgr 的块设备 Session，保存容量、只读状态、flush 能力和已占用卷范围。
文件系统块大小为 4096 字节。
每次磁盘读写使用页框缓冲提交请求，等待完成并 ACK，再核对状态和实际字节数。

磁盘请求带递增标识。
请求未能完成确认时，Disk 保存失败状态，后续操作返回错误。
卷的挂载和卸载分别登记、释放其磁盘范围。

## ext4 磁盘结构

挂载从 superblock 开始，检查容量、块大小、特征位、组布局和 inode 大小。
当前接受 4096 字节块、128 或 256 字节 inode，使用 extent 和带类型的目录项。
识别的特征包含内部 journal、恢复标记、sparse superblock 与 large file。

卷保存块组、块与 inode 位图、inode 表、块缓存和打开节点身份。
查找文件时，目录项给出 inode，inode 中的 extent 再把文件逻辑块转换为磁盘块。
读取遇到空洞或未写入 extent 时返回零，越过文件末尾时按实际内容长度完成读取。

可写卷通过分配器更新块和 inode，维护 extent、目录内容、链接计数与属性。
打开节点保存 inode 身份。
删除目录项后，已打开的文件会话继续持有该节点，回收随节点引用和链接状态推进。
无 journal 的合法卷通过只读路径访问。

## 事务、同步与恢复

一次创建文件会同时改变目录项、inode 和分配位图。
fs 将这类修改块暂存在同一个事务中，再写入 journal，完成后更新它们在卷中的位置。
操作校验失败时清除暂存项；提交前检查 journal 容量和设备 flush 能力。
JBD2 提交写入 descriptor、数据和 commit 记录，并计算 CRC32C 校验。
提交后同步设备，再将修改写入目标块并同步，最后更新 journal 状态。

卷第一次修改时更新磁盘上的 dirty 与恢复状态。
`fsync` 从 File 会话进入卷同步路径，再通过块设备执行 flush。
文件同步由这条服务调用链落实到设备。

挂载时若存在恢复状态，读取并验证 journal 中的事务，重放有效更新。
孤儿 inode 链用于恢复链接数已归零的节点与释放其资源。
恢复完成后更新卷状态。

事务提交或同步发生 I/O 错误后，卷保存失败结果并拒绝继续写入。
卸载检查打开引用，完成同步、更新 clean 状态并释放磁盘范围。

## 文件客户端示例

下面的函数借用已有文件客户端，打开并读取配置：

```rust
fn read_config(
    files: &fs::Client<'_>,
    output: &mut [u8],
    deadline: u64,
) -> Result<usize, fs::Error> {
    let file = files.open("/etc/init.toml", deadline)?;
    file.read_at(0, output, deadline)
}
```

`read_at` 返回本次读取字节数，文件末尾可以使结果短于输出切片。
`ReadAt::read_exact_at` 继续读取直到填满切片，或返回相应错误。
